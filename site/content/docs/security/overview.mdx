description: How Studio handles sign-in, user data, secrets, model calls, and FFmpeg.

## Sign-in and sessions

Google is the only sign-in control on `/login`. The session cookie is `HttpOnly` and `SameSite=Lax`, and `Secure` in production. A signed-out request to any private route redirects to `/login`, and JSON clients get `401`.

## Isolation

Every job query includes the signed-in user's id. Another user's job, download, captions, retry, and pack all answer `404`, so job ids do not reveal what exists.

## Input

The brief is validated on the server. The style must be a known skill id, so a brief cannot name a path. Facts and links have count and length limits, and links must be `http` or `https`.

## Secrets

API keys, the OAuth secret, and `APP_KEY` come from the environment. They are not in the repository, the image, logs, or job rows. A provider error is reduced to its HTTP status before it is stored, and a missing key is reported by variable name only.

## FFmpeg

Commands are argument lists, never shell strings. Captions are burned from an SRT file, never spliced into a filter string. A plan is rejected when a caption has control characters, braces, or backslashes (libass would read them as styling), or is over 500 characters. Every encoder, probe and renderer process has a deadline and is killed when it passes. The output is accepted only after the QA checks in [QA](/docs/pipeline/qa) pass.

## Spend

Each job is capped by output tokens and by a worst-case cost limit, each user has a rolling 24-hour job limit, and a job renders at most five times. The limits are enforced inside database transactions and conditional updates, so parallel requests cannot pass them.

## Continuous checks

The `security-audit` skill (Cloudflare, vendored under `.agents/skills/security-audit`) runs in guidance mode on pull requests together with `govulncheck`. Betterleaks scans for committed secrets, and OpenSSF Scorecard tracks repository hygiene.

Report a vulnerability as described in `SECURITY.md`.
